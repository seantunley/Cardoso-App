## Codebase Patterns
- server.js uses ESM (import/export) — all new src/ files must also use import/export (package.json has "type": "module")
- `createRequire(import.meta.url)` is used for JSON imports (e.g., package.json)
- db singleton: src/db/index.js exports the db instance. All modules import from there — never open new Database()
- HUB_MODE routes: wrap in if (process.env.HUB_MODE === 'true') checks
- Versioned migrations: src/db/migrations.js exports buildMigrations(db) and runMigrations(db)
- Schema init: src/db/schema.js exports initSchema(db) — PRAGMAs, CREATE TABLEs, indexes, custom field config, migrations
- Prepared statements: src/db/statements.js exports buildStatements(db)
- server.js had pre-existing merge corruption from commit 47c41c5 — restored from 4a0e196 (last valid commit)
- Auth middleware: createAuthMiddleware({ getUserById, sanitizeUser }) factory pattern — dependencies injected from server.js
- Rate limiter: standalone export from src/middleware/rateLimit.js
- Field registry: src/fieldRegistry.js exports FIELD_REGISTRY, INVOICE_SLOTS, RECEIPT_SLOTS, buildFieldPatch, buildDynamicLocalFieldsPatch, and mapping helpers
- Shared helpers: src/helpers.js exports sanitizeForSqlite, parseJsonSafely, stringifyJsonSafely, expandDataRecord, normalizeFieldKey, validateCustomFieldKey, boolFromRow, defaultPermissionsForRole, sanitizeUser, sanitizeConnection
- fieldRegistry.js imports parseJsonSafely from helpers.js — no circular deps since neither imports from routes/services
- Auto-flag service: src/services/autoFlag.js exports _evalCondition, _evalRuleConditions, applyAutoFlagRulesToRecord — pure functions, no deps
- Auth router: createAuthRouter({ db, stmts, getUserById, requireAuth, requireAdmin, requireSelfOrAdmin, loginLimiter }) factory pattern
- Route files use express.Router() and full paths (e.g., '/api/auth/login'), mounted with app.use(router)
- Records router: createRecordsRouter({ db, stmts, requireAuth, requireAdmin, requirePermission, checkTableAccess }) — owns schema cache, custom-fields, record history, auto-flags, dynamic CRUD
- Schema cache (allowedTables, isValidTableName, getTableColumns) lives in records router — only used by CRUD routes
- Connections router: createConnectionsRouter({ db, requireAuth, requirePermission, isShuttingDown }) — owns test-connection, test-query, import (runConnectionImport now imported directly from syncEngine)
- Sync engine: src/services/syncEngine.js exports runConnectionImport, acquireSyncLock, releaseSyncLock, activeSyncs — module-level exports, imports db singleton directly
- runConnectionImport accepts optional 2nd arg { isShuttingDown } — callers pass the getter to enable shutdown-aware sync
- Hub ETL: src/services/hubEtl.js exports initHubTables, initHubSiteRegistry, syncAllSites, runHubBackupPull, HUB_SITES — imports db singleton and buildStatements internally
- Hub router: createHubRouter({ requireAuth, requireAdmin }) — imports db, stmts, boolFromRow, bcrypt, syncAllSites, HUB_SITES directly (no injection needed)
- Non-hub fallback: createNonHubFallbackRouter() returns empty-response stubs for hub endpoints on non-hub installs
- Hub table creation (initHubTables) must be called before hub router or ETL — tables needed for prepared statements
- Reporting router: createReportingRouter({ requireAuth }) — owns KPIs, top-balances, inventory, and /api/reporting/* multi-site endpoints
- Backup router: createBackupRouter() — no deps injected, imports db/dbPath singleton directly
- System router: createSystemRouter({ requireAuth, requireAdmin }) — owns app-info, version-status, auto-update trigger + background hourly check
- requireReportingToken middleware lives in reporting.js (module-scoped, not exported) — used only by /api/reporting/* routes
- record_snapshots: append-only audit table (migration v9) — INSERT only, never UPDATE/DELETE. Snapshots inserted per-record in syncEngine.js runWriteRows
- Startup logic: src/startup.js exports validateSessionSecret, migrateUnencryptedPasswords, recoverAbandonedSyncs, ensureSeedUsers, createGetUserById — imports db singleton directly
- Scheduler/lifecycle: src/scheduler.js exports isShuttingDown, startSchedulers, startHubSchedulers, setServer, gracefulShutdown — owns all cron tasks, intervals, and shutdown logic
- server.js is now a thin entry point (79 lines): imports, middleware config, router mounting, and startup — no business logic, no SQL, no crypto
- Health endpoint: GET /api/health (unauthenticated) in system router — returns { status: 'ok' }
- Smoke test: scripts/smoke-test.sh — syntax checks, build, and health check automated

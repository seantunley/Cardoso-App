# Release notes — 2026-05-08

A single-day audit-driven push: 22 pull requests covering performance, reliability, security hardening, observability, tests, and documentation across every major module (hub, OCR, backup, customer, reconciliation). Every fix has a regression-test or comment-block recording the *why* so future-you doesn't reintroduce the bug.

This isn't a normal release cadence — most days are calmer. It's the result of a sequence of external module reviews (OCR, backup, customer, reconciliation) plus a cross-codebase performance audit. Each batch came in, got triaged, and shipped as separate small PRs to keep the merge units reviewable.

## What ships (by module)

### Hub aggregation

- **#202 perf(hub): parallelise fan-out + collapse KPI rollup queries** — `pingAllSites` no longer serialises 5s timeouts per offline site; backup-pull integrity-check + .env-fetch run in parallel; records/inventory pagination uses depth-2 prefetch; `/api/hub/kpis` collapsed from 17 queries to 2.
- **#203 perf(hub-dashboard): memoise tree + GLOB sub-account lookup** — `SiteCard`, `HubCustomerModal`, `HubCustomerSearch` wrapped in `React.memo`; search debounce tightened to 300ms; sub-account lookup uses SQLite `GLOB '<parent>[^0-9]*'` instead of LIKE+JS-regex.
- **#198 Hub: site→Accpac freshness + 'Sync from Accpac' trigger button** — hub tiles show site-side Accpac sync state; one-click trigger initiates a fresh sync.
- **#200 hub_sites: soft-tombstone orphans + Forget flow + tile redesign** — orphaned hub_sites entries marked rather than hard-deleted; admin "Forget" flow surfaces them.
- **#197 Settings: remove duplicate System Log + Updates tabs** — those tabs already exist under Operations; the Settings copies were redundant.

### OCR pipeline

- **#206 fix(ocr): recycle OCR worker on row/RSS budgets** — addresses the production memory leak (RSS hit 18 GB on one site at t+420s). Two budgets, both env-tunable: `OCR_LANE_ROW_BUDGET` (default 25 rows) and `OCR_LANE_RSS_BUDGET_MB` (default 2 GB). NaN-guarded env parsing; observability failures can no longer disable the recycle path.
- **#207 fix(ocr): security hardening** — Google Vision auth via `X-Goog-API-Key` header instead of `?key=` URL param; SHA-256 cap on PDF download size (`OCR_MAX_PDF_MB`); SSRF guard rejecting private/loopback/Tailscale-range PDF URLs (`OCR_PDF_ALLOWED_HOSTS` allowlist).
- **#208 feat(ocr): structured timeout errors + match-trace artifact** — `err.code = 'OCR_TIMEOUT'` replaces a regex-on-message classifier; every successful match emits `{ source, engine, angle }` so an operator can audit "which path produced this number".
- **#209 docs: deferred OCR review items** — captures rotation-angle expansion, regex-pack externalisation, per-job cancellation, and adaptive engine ordering with explicit revisit triggers.

### Backup module

- **#210 fix(backup): security hardening** — auth-failure logging (route + IP + UA, never the token); strict per-IP/token rate limits on `/download` and `/config` (`BACKUP_HEAVY_MAX_PER_HOUR`); hardened `.env` redaction (URL userinfo, multi-line PEM blocks); `Cache-Control: no-store`; env-tunable stale-snapshot TTL.
- **#211 feat(backup): audit trail + SHA-256 transport integrity** — every successful and failed export logged to `auditlog`; download exposes `X-Backup-SHA256` header for hub-side verification; lifecycle listeners attached before pre-stream work so disconnects during snapshot/hash phases are recorded; SHA-256 hash pipeline aborts on client disconnect; cleanup guard handles pre-tmpPath disconnects correctly.

## Operator smoke tests post-deploy

Lightest-touch checks that will catch the highest-value regressions:

- **OCR**: Run a recon batch that crosses the 25-row budget. Confirm `bat.ocr.lane_recycle` info logs appear and RSS doesn't climb past ~2 GB.
- **Backup**: Hit `/api/backup/download` with a bad token 11 times in an hour from one IP — 11th request should 429.
- **Hub KPIs**: Open Hub Dashboard. Switch the `dateRange` filter. Confirm tiles still render correct totals with the new single-query rollup.
- **Sage status pill**: Open the Reconciliation page. Confirm a green "Sage OK" pill near the title with hover-tooltip showing last-probe timestamp.
- **Customer search**: Type a parent customer code (e.g. `100`). Confirm sub-accounts (`100A`, `100-1`) appear in the modal and `1001` does NOT.
- **Backup audit trail**: After one hub backup-pull cycle, run `SELECT * FROM auditlog WHERE action = 'backup_db_exported' ORDER BY id DESC LIMIT 5` — should show one row per pull with status='success'.

## Review-cycle notes

Every PR went through Codex automated review. The cycle this taught us:

- **Force-push during CI causes false-positive secret-scan failures** (gitleaks can't compute a diff against a rewritten commit). Cosmetic; ignore the notification when the current HEAD is green.
- **`logError` is sync I/O on every call** — calling it on hot paths is a production performance regression. Telemetry on per-keystroke endpoints belongs in an in-memory bucket pattern (like `securitySignals`), not in `logError`.
- **`res.send`/`stream.on('end')` are NOT flush-to-client signals.** Audit success has to hang off `res.on('finish')`; lifecycle listeners must be attached *before* awaits that span seconds (snapshot, hash) so a disconnect during pre-stream work still gets recorded.
- **`db.transaction(...)` nesting via savepoints is your friend.** Wrapping outer code that calls into already-transactional helpers does the right thing — the inner txn becomes a savepoint inside the outer transaction.
- **Codex catches the kind of subtle stuff humans miss.** Several P1-flagged regressions tonight were "this looks fine but actually..." catches that would have shipped without review. Worth keeping in the loop.

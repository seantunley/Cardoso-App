# 30/60/90 Roadmap

**Start date:** May 5, 2026  
**End date:** August 3, 2026

## Phase 1 (Day 0–30): Reliability & Operator Visibility
**Window:** May 5, 2026 → June 4, 2026

### Goals
- Make background operations observable and controllable.
- Reduce silent-failure risk.
- Improve admin confidence during incidents.

### Deliverables
1. **Job Control Center (MVP)**
   - Unified Jobs page for sync/OCR/backup/reconciliation workers.
   - Display: status, last run, next run, duration, last error.
   - Manual actions: run now, retry, pause/resume (admin-only).
2. **Alerting Foundation**
   - Event rules for critical failures (sync fail, OCR fail, backup fail, repeated auth issues).
   - Basic delivery channel (email first; Slack/Teams later).
   - Alert de-duplication and cooldowns.
3. **Ops Audit Trail**
   - Track manual job actions (who did what, when, result).
   - Link actions to existing error/system logs.

### Suggested implementation
- Add `job_runs` and `job_controls` tables.
- Standardize job lifecycle hooks: `started`, `succeeded`, `failed`.
- Add endpoints:
  - `GET /api/system/jobs`
  - `POST /api/system/jobs/:id/actions`
- Build admin Jobs UI with periodic refresh.

### Acceptance criteria
- Admin can view all critical jobs and retry failed ones.
- Critical job failures alert within 60 seconds.
- All manual job actions are auditable.

### Risks
- Race conditions between scheduler and manual triggers.
- Alert fatigue without threshold tuning.

## Phase 2 (Day 31–60): Access Transparency & Data Quality
**Window:** June 5, 2026 → July 4, 2026

### Goals
- Make permission decisions explainable.
- Improve trust in reconciliation/reporting data.
- Reduce support time for access-related issues.

### Deliverables
1. **Permission Visibility + Simulator**
   - “Why denied?” admin view per user/page.
   - Role/permission simulator before save.
   - Exportable permission matrix.
2. **Data Quality Dashboard (MVP)**
   - KPIs: duplicates, missing fields, reconciliation mismatches.
   - Trends by source/system/week.
   - Top Issues queue (new/in review/resolved).
3. **Saved Views / Presets**
   - User-level saved filters for reports/reconciliation.
   - Optional shared team presets.

### Suggested implementation
- Reuse existing permission-check logic in API as source of truth.
- Run quality checks as scheduled jobs (nightly + on-demand).
- Add `quality_findings` table keyed by entity/source/date.

### Acceptance criteria
- Admin can diagnose any access denial in under 2 minutes.
- At least 3 recurring quality checks run automatically.
- Users can save and load named report presets.

### Risks
- Simulator drift from route guards if logic diverges.
- False positives if quality thresholds are too strict.

---

## Phase 3 (Day 61–90): Performance, Config Safety & Scale
**Window:** July 5, 2026 → August 3, 2026

### Goals
- Improve API performance visibility.
- Reduce production risk from config changes.
- Improve incident response and postmortem quality.

### Deliverables
1. **API Observability**
   - Per-route latency and error metrics (p50/p95/p99).
   - Throughput by route and role.
   - Slow endpoint dashboard.
2. **Config Safety Checks**
   - Runtime config page (secret-safe redaction).
   - Validation warnings for risky env combinations.
   - “Restart required” indicators.
3. **Incident Timeline**
   - Unified timeline: deploy/restart, job events, alerts, manual interventions.

### Suggested implementation
- Instrument Express middleware for latency/status metrics.
- Store rollups in time buckets (minute/hour) with retention.
- Add config-check endpoint and system UI panel.
- Correlate events by timestamp, component, optional run ID.

### Acceptance criteria
- Operators can identify top slow endpoints from dashboard.
- Unsafe config states are clearly flagged.
- Incident review can be done from a single timeline view.

### Risks
- Metrics storage overhead without retention controls.
- Config overexposure if redaction is incomplete.

---

## Recommended cadence
- Weekly flow: planning (Mon), build (Tue–Thu), stabilize/demo (Fri).
- Release every 2 weeks with rollback checklist.
- “Done” includes tests, instrumentation, and auditability.

## KPI targets by August 3, 2026
- MTTR for job failures: reduce by 40%.
- Access-related support tickets: reduce by 30%.
- Undetected failed jobs older than 4 hours: near zero.
- p95 latency on key routes: reduce by 20%.
- Reconciliation exceptions older than 7 days: reduce by 25%.
